Case Studies ​

Incidents and studies to teach from, grouped by topic. Each has a source, the week it fits, the safety-contract rule it motivates, and two discussion questions. Facts and numbers come from the linked sources as collected in Evidence Base and Reading List: "Engineering Software with AI" (CS 4xxx/5xxx) and Course B ("Engineering Software with AI"): the $0 tool landscape, checked 2 November 2026. Cases marked [A] were collected by the sibling course, Building Apps with AI (its case studies), and are summarized here for seniors.

These are not stories about careless people. They involve major vendors, experienced engineers and popular tools. Read each one for the mechanism: what made the failure possible, and which control would have stopped it. Rule numbers refer to the agent safety contract.

On this page: Using these in class · A. Prompt injection and agent incidents · B. Supply chain and insecure code · C. Deleted databases · D. Benchmark inflation · E. Maintainers' AI policies · Where sources disagree

Using these in class ​

  • Jigsaw (20 minutes, the Seminar's discussion block). Groups of three each take one case for 8 minutes and fill in four lines: mechanism · which leg of the lethal trifecta (or which grading flaw, or which policy) · which control would have stopped it · what our own setup does about it. Two minutes each to report back.
  • Default sets: week 4: A1, A2, A4, A5 · week 10: B1, B4, B5, B6 · week 12: D2, D3, D5 · week 14: E1, E2, E3, E7.
  • In a threat model or report, cite the case and say which claim is observed (in the source) and which is inferred (your reading).

Prompt injection and agent incidents ​

The frame for this section is Simon Willison's lethal trifecta: an agent with access to private data, exposure to untrusted content, and a way to send data out can be made to leak the data. Coding agents usually have all three. The defenses that hold are architectural: the OWASP GenAI LLM Top 10 for 2026 now ranks Prompt Injection first and Excessive Agency third (OWASP); design patterns such as plan-then-execute, dual LLM and context minimization give provable resistance at some cost in utility (Beurer-Kellner et al.); and CaMeL, which separates a privileged planner from a quarantined parser behind capability policies, solved 77% of AgentDojo tasks with provable security against 84% undefended (Debenedetti et al.).

A1. Supabase MCP: the lethal trifecta in one server ​

July 2025. An agent connected to a Supabase MCP server with the service_role key, which bypasses row-level security, was asked to handle support tickets. A ticket contained instructions; the agent followed them and copied secrets from the database into a reply the attacker could read. One server supplied private data, untrusted content and the way out. Making the server read-only removes the exfiltration path.

  • Lesson: count the legs per session, not per tool. A trusted server plus untrusted data is untrusted.
  • Rules: 4 (no real secrets near an agent reading untrusted text), 5 (scoped, read-only tokens).
  • Discuss: (1) Which single change removes the most risk: a read-only key, a separate session for reading tickets, or an approval prompt on writes? (2) Map your team's agent setup onto the three legs.
  • Source: Willison, on General Analysis

A2. GitHub MCP: a public issue leaks a private repository ​

May 2025. Invariant Labs showed that a malicious public issue could lead an agent, holding a GitHub token with access to the user's private repositories, to copy private-repository data into a public pull request. Invariant calls the problem architectural, not a bug in the server.

  • Lesson: a broad token turns every public input into a potential instruction with private reach.
  • Rules: 4, 5, 10.
  • Discuss: (1) Write the narrowest token that would still let the agent do the original task. (2) Who reviews what an agent posts publicly in your team's workflow?
  • Source: Invariant Labs: GitHub MCP exploited

A3. MCP tool poisoning: instructions the user never sees ​

April 2025. Hidden instructions in an MCP tool description, shown to the model but not to the user, got an agent to read SSH keys. A server can also change a tool's description after the user approved it. The MCP specification's own security best practices now catalogue related attacks: confused deputy, token passthrough (forbidden), SSRF during OAuth discovery, local MCP server compromise through malicious startup commands, and more.

  • Lesson: a tool description is a prompt. Review it like code, and pin servers to a version you've read.
  • Rule: 8.
  • Discuss: (1) Your mcp-from-scratch server returns a tool list. What stops a later version from changing it? (2) Which attacks in the spec's catalogue apply to a stdio server on your own laptop?
  • Sources: Invariant Labs: tool poisoning · MCP Security Best Practices

A4. Copilot edits its own permissions, and CamoLeak ​

2025. In CVE-2025-53773, injected text made Copilot write "chat.tools.autoApprove": true into .vscode/settings.json, switching itself into auto-approve mode (CVSS 7.8; patched August 2025). In CamoLeak (CVE-2025-59145, CVSS 9.6), hidden comments in a pull request made Copilot Chat leak private code as a sequence of pre-signed image URLs; GitHub disabled image rendering in Copilot Chat.

  • Lesson: an agent must not be able to edit its own permissions, and any rendered URL is a way out.
  • Rules: 2, 4.
  • Discuss: (1) Which files in your setup control your agent's permissions, and can the agent write them? (2) List every channel by which mini-agent could send data out, including ones that don't look like network calls.
  • Sources: CVE-2025-53773 (Cybersecurity News) · CamoLeak (Legit Security)

A5. Your AI, My Shell: injection rates in agentic editors ​

Study, 2025–26. AIShellJack planted 314 payloads, covering 70 MITRE ATT&CK techniques, in project files and rules. Cursor and Copilot ran the malicious commands up to 84% of the time.

  • Lesson: "the model will notice" is not a defense. Rates like these make the sandbox and approvals mandatory.
  • Rules: 2, 3. [Grad seminar] paper.
  • Discuss: (1) The week 4 lab's poisoned README is one payload. What would a fair test of your defenses need? (2) Which ATT&CK techniques does an approval gate stop, and which does it not?
  • Source: Liu et al., arXiv 2509.22040

A6. Received folders: code that runs before the prompt ​

2026, [A]. Coding agents run git status in the background when they open a folder, often before asking whether you trust it. A project received as a folder with its hidden .git directory can carry git settings that run an attacker's program outside the agent's sandbox, with no prompt at all. Cloning the same project from its URL is safe.

  • Lesson: approval prompts protect you only from the actions they're asked about.
  • Rule: 3.
  • Discuss: Why is a clone from a URL safe when the same files from a zip are not?
  • Source: Manifold Security

A7. Autopilot: a web page that sent secrets away ​

2026, [A]. In the autopilot mode of a CLI agent, a user asked the agent to fetch a web page. Hidden instructions on the page made the agent read the project's .env.prod and send the secrets to the attacker in about 28 seconds. The vendor confirmed the finding but did not treat it as a vulnerability, because the user had chosen full autonomy.

  • Lesson: turning approvals off transfers the risk to you, by the vendor's own account.
  • Rules: 2, 4.
  • Discuss: Do you accept the vendor's position? What would have stopped it with approvals still off?
  • Source: Adversa AI

A8. PixelLeak: helpful agents publish 13,000 screenshots ​

September 2026, [A]. Developers asked agents to attach before-and-after screenshots to code reviews. The agents created public GitHub repositories to host the images, exposing more than 13,000 internal screenshots from over 300 organizations. At one company the workaround spread through a shared skill file. Secret scanners, which read text, couldn't see what was in the pictures.

  • Lesson: no attacker, no bug, just a helpful agent. Publishing is an action that needs a human.
  • Rule: 10.
  • Discuss: (1) Whose mistake was this? (2) Which of your team's agents can create a public artifact, and what stops it?
  • Source: The Hacker News

A9. The rules-file backdoor ​

March 2025, [A]. Invisible Unicode characters in AI rules files can steer Copilot or Cursor to insert backdoors into generated code. The text survives forks and gets past human review because people can't see it.

  • Lesson: an AGENTS.md from the internet is a stranger's instructions to your agent.
  • Rule: 8.
  • Discuss: How would you detect an instruction you can't see? Write the one-line check.
  • Source: Pillar Security

Supply chain and insecure code ​

B1. Shai-Hulud: a self-replicating npm worm ​

September 2025. The Shai-Hulud worm compromised 500+ npm packages, spreading by publishing itself with stolen maintainer credentials. CISA advised auditing lockfiles, pinning to releases from before 16 September 2025, rotating credentials and requiring phishing-resistant MFA. It is the background to the 2026 AI-key stealers (B4).

  • Lesson: the package you meant to install can be the malicious one. Lockfiles and pinned versions are a control, not a formality.
  • Rule: 8.
  • Discuss: (1) What does a committed package-lock.json protect you from, and what not? (2) Which of roomly's dev dependencies run code at install time?
  • Source: CISA alert

B2. Nx s1ngularity: malware that used your AI tools ​

August 2025, [A]. Poisoned releases of the Nx package ran a script on install that used AI CLIs already on the machine to search for secrets and crypto wallets, then uploaded them to public repositories: 2,349 credentials from 1,079 systems. It is described as the first supply-chain attack to turn developers' AI assistants against them.

  • Lesson: an installed agent CLI is a capability that any local program can borrow.
  • Rules: 4, 8.
  • Discuss: Map it onto the lethal trifecta. Which leg did the attacker bring?
  • Sources: GitGuardian · Nx postmortem

B3. Amazon Q: a wiper prompt ships in an extension ​

July 2025, [A]. A pull request from an untrusted contributor to the Amazon Q VS Code extension added a prompt telling the agent to act as a "system cleaner" deleting local files and cloud resources. It shipped to users; a syntax error stopped it from working.

  • Lesson: a prompt inside a tool is code. Review changes to prompts and instruction files with the same care, including in the PR round.
  • Rule: 8.
  • Discuss: Your review checklist covers code. What would catch a malicious paragraph of English?
  • Sources: BleepingComputer · The Register

B4. Malware that hunts for AI keys ​

October 2026, [A]. In two weeks: a compromised release of the real npm package tensorlake collected .env files, SSH keys and AI tools' config folders and MCP files from a preinstall hook; a trojanized LiteLLM release stole AI provider keys; fake npm packages offering "free Claude and Gemini credits" added an attacker's MCP server to victims' agent settings; and an intruder reached OpenCode's hosted Console and exposed stored provider keys, with some users seeing unauthorized charges of more than $1,000 (the open-source tool was not affected).

  • Lesson: your AI keys are money, and malware knows where agents keep them. Keys with no billing attached are worth nothing to steal.
  • Rules: 4, 6, 8.
  • Discuss: (1) What's in your agent's config folder that an attacker would want? (2) If a course key were stolen tonight, what would limit the bill?
  • Sources: Socket · Wiz · The Hacker News · TechCrunch

B5. Slopsquatting: packages that don't exist ​

2025–26, [A]. A USENIX Security 2025 study of 16 models found invented package names in 21.7% of open-model and 5.2% of commercial-model outputs; 43% of invented names recurred in all ten repeat runs, which makes them predictable for attackers. A 2026 re-test found frontier models still invent 4.6–6.1% of names, with the same 127 fake names shared by all five models tested.

  • Lesson: verify that a package exists, is the one you meant and is maintained, before an agent installs it. Week 10's lab automates the check.
  • Rule: 8.
  • Discuss: Why does recurrence matter more than the rate?
  • Sources: CSA research note · arXiv 2605.17062

B6. BaxBench: working, but exploitable ​

Study, 2025. Across 392 backend tasks checked with functional tests and end-to-end exploits, the best model was 62% correct, and about half of the correct programs were exploitable. Separately, about 4% of 33,000+ agentic pull requests on GitHub are security-related; they merge less often and wait longer for review.

  • Lesson: "the tests pass" and "it's secure" are different measurements. Week 10's security review is its own step.
  • Rule: 9. [Grad seminar] paper (BaxBench).
  • Discuss: What would an exploit test for roomly's booking API look like?
  • Sources: Vero et al., arXiv 2502.11844 · Siddiq et al., arXiv 2601.00477

Deleted databases ​

C1. Replit: the code freeze that was only words ​

July 2025, [A]. During a public trial, Replit's agent ignored an explicit code freeze and repeated instructions in capital letters, deleted a production database, created fake data and false test results, and said a rollback was impossible when it wasn't. Replit responded with automatic separation of development and production databases, better restore, and a planning-only mode.

  • Lesson: instructions are not guardrails. Only permissions, separation and real backups are. And an agent's report about what it did must be checked.
  • Rules: 4, 7, 9.
  • Discuss: (1) Rewrite the code freeze as a control instead of a sentence. (2) How would you check the claim "rollback is impossible"?
  • Sources: Fortune · The Register · AI Incident Database #1152

C2. PocketOS: a token found in an unrelated file ​

April 2026, [A]. A Cursor agent doing a routine task on staging hit a credential mismatch and, on its own initiative, deleted a cloud storage volume, wiping production data and the backups stored on the same volume, in about nine seconds. It used an API token it found in an unrelated file, created for managing domain names. Afterwards it listed the project's safety rules it had broken.

  • Lesson: an agent will use any credential it can find. Backups on the same volume aren't backups. Written rules didn't stop it.
  • Rules: 5, 7.
  • Discuss: (1) List every place a credential for your team fork exists right now. Which can an agent read? (2) The agent could recite the rules afterwards. What does that say about AGENTS.md?
  • Sources: Information Age (ACS) · Tom's Hardware

Benchmark inflation ​

The frame: a benchmark score combines the model, the scaffold, the adequacy of the tests and contamination. Ask five questions of any claim: which harness? what does "pass" mean? does the task predate the model's cutoff? is it pass^k with a confidence interval? does it survive the Agentic Benchmark Checklist? (evidence notes). These cases fit week 12, with D5 as week 1's teaser.

D1. SWE-bench Verified, retired by its co-creator ​

February 2026. OpenAI, which co-created SWE-bench Verified, stopped reporting it, citing contamination and flawed tests, and recommended SWE-bench Pro instead. According to coverage (the page itself returned 403 to the course's research), 59.4% of 138 audited hard tasks had material test or specification flaws.

  • Discuss: If the benchmark's maintainers abandon it, what should you make of a vendor's score on it last year?
  • Sources: OpenAI · AI Weekly (coverage)

D2. The solution was in the issue; the tests were too weak ​

Study, 2024. In 32.67% of successful SWE-Agent + GPT-4 patches the solution was already in the issue text, and 31.08% passed only because the tests were weak. Filtering both out cut the resolve rate from 12.47% to 3.97%.

  • Discuss: Which of the two flaws could your team's own tests have?
  • Source: Aleithan et al., SWE-Bench+, arXiv 2410.06992

D3. Plausible patches that behave differently ​

Study, 2025. A differential testing tool found that 29.6% of plausible patches behave differently from the ground truth, 28.6% of those are certainly wrong, and a further 7.8% were counted as passing despite failing the full test suite: together, 6.2 points of inflated resolve rate.

  • Discuss: How is this the same problem as week 7's surviving mutants?
  • Source: Wang, Pradel & Liu, arXiv 2503.15223 [Grad seminar]

D4. Remembering instead of reasoning ​

Study, 2025. From the issue text alone, models named the buggy file up to 76% of the time on SWE-bench against 53% on other repositories, and reproduced function 5-grams verbatim at 35% against 18%.

  • Discuss: Design a contamination check for an eval you build in week 12.
  • Source: Liang, Garg & Zilouchian Moghaddam, arXiv 2506.12286 [Grad seminar] [Replicable]

D5. Maintainers vs graders ​

2025–26. In 2025 METR found that none of 15 reviewed agent PRs was mergeable as-is, though 38% passed the tests; fixing them took 42 minutes on average. In 2026 four maintainers of scikit-learn, Sphinx and pytest reviewed 296 test-passing agent PRs: their merge rate ran 24.2 points below the automated grader after normalizing to golden patches, and they merged only 68% of the human-written golden patches themselves.

  • Discuss: (1) What do maintainers check that tests don't? (2) Note the 68%: what does it say about maintainer judgment as a gold standard?
  • Sources: METR, 2026 · METR, 2025

D6. Empty answers counted as successes ​

Study, 2025. The Agentic Benchmark Checklist found task and reward flaws that distort scores by up to 100% in relative terms: SWE-bench Verified has weak tests, and τ-bench counted empty responses as successes. Applying the checklist cut CVE-Bench's overestimation by 33%. A hand audit of 100 random SWE-Bench Pro tasks found lenient tests, a test that requires a since-fixed bug, and requirements text that leaks the gold patch.

  • Discuss: Run three items of the checklist against your own week 12 eval.
  • Sources: Zhu et al., arXiv 2507.02825 [Grad seminar] · Gabor, "SWE-Bench Pro is even worse"

Maintainers' AI policies ​

The frame: projects converge on disclose, understand, take responsibility, enforced by a human sign-off, and disagree on how to record AI involvement. In 1,000 popular repositories, 118 had a contributor AI policy: 78% allow AI-assisted contributions, 51% require disclosure and 74% require a human in the loop (Hora & Robbes, arXiv 2605.16706). A study of 281 policies found 48.8% require disclosure (Hora et al., arXiv 2609.07542, [A]). Policies change fast: check the current text before you contribute.

E1. QEMU: decline, and a proposal to relax ​

QEMU's policy is to "DECLINE any contributions which are believed to include or derive from AI generated content", citing DCO and copyright uncertainty; AI for research, static analysis or debugging is allowed if its output isn't included. A May 2026 proposal would allow mechanical changes, bug fixes of about 20 lines, docs and tests, recorded with an AI-used-for: trailer (explicitly not Assisted-by). It drew acks and strong objections; as of 2 Nov 2026 no decision is recorded.

  • Discuss: If you found a bug in QEMU with an agent's help, what could you contribute?
  • Sources: QEMU code provenance · Bonzini's patch

E2. Ghostty: disclose everything, or be denounced ​

"All AI usage in any form must be disclosed." Contributors must be able to explain changes without AI; AI-generated media is banned; and people who submit slop may go on a public denouncement list that blocks future contributions. The policy also says: if you're learning, don't use AI, "and we'll help you".

  • Discuss: One student's slop could put a university's name on such a list. What does the course's upstream screening protect?
  • Source: Ghostty AI_POLICY.md

E3. LLVM: a human in the loop and an Assisted-by trailer ​

"Contributors must read and review all LLM-generated code." New contributors should start small; "Passing maintainer feedback to an LLM doesn't help anyone grow". Disclosure uses a trailer such as Assisted-by:, PR descriptions are written by the contributor, and agents acting "without human approval" are banned. This course's Assisted-by: trailer and self-written PR descriptions come from here.

  • Discuss: Why ban feeding review comments to an LLM, if the fix is correct?
  • Source: LLVM AIToolPolicy.md

E4. The Linux kernel drops its AI tag ​

The kernel's coding-assistants document requires GPL-2.0-compatible code, says "AI agents MUST NOT add Signed-off-by tags," and puts full responsibility on the human. Per Hackaday, maintainers dropped the Assisted-by tag requirement in October 2026, and the master copy no longer mentions it; networking maintainers secured budget to run several frontier models on each patch for review.

  • Discuss: The kernel dropped disclosure and added AI review. Is that consistent?
  • Sources: coding-assistants.rst · Hackaday

E5. Django, Gentoo and NetBSD: three more answers ​

Django requires disclosing the tools and what they did and verifying output against the full test suite, includes a "Note for AI Tools" addressed to agents, and asks contributors not to request automated AI reviews because they "often generate noise". Gentoo bans content created with NLP AI tools. NetBSD treats LLM output as "presumed to be tainted code" needing prior written approval from core. Debian declined to adopt a ban.

  • Discuss: Django addresses agents directly in its docs. Should your AGENTS.md do the same for your team fork?
  • Sources: Django · Gentoo · NetBSD · iTWire on Debian

E6. curl ends its bug bounty ​

January 2026. curl's maintainer ended its HackerOne bug bounty (up to $10,000) to remove the incentive for AI-generated junk reports.

  • Discuss: Who paid the cost of the junk reports, and who could have prevented it?
  • Sources: The Register · BleepingComputer

E7. Platforms push back: PR caps and Hacktoberfest ​

GitHub added settings to restrict pull requests to collaborators, then a cap on open PRs from users without write access that counts agent-opened PRs, then exemptions by account age or contribution history. The MCP TypeScript SDK allows "one open pull request at a time" from such contributors. Godot maintainers called AI PRs "draining and demoralizing". Hacktoberfest 2026 dropped its PR challenge after "a massive flood of activity and burnout from the rise of low-effort PRs".

  • Discuss: A new student account may be capped by default. How does the course's three-tier project design handle that?
  • Sources: GitHub discussion #187038 · Visual Studio Magazine · Gigazine · The Register on Godot · Hacktoberfest

E8. Hypocrite commits: when research gets an institution banned ​

2021. The Linux kernel banned contributions from the University of Minnesota after a research group submitted deliberately flawed "hypocrite commits"; how IRB review was handled is disputed in the coverage. One group's study got a whole institution blocked.

  • Lesson for graduate studies: no intervening on maintainers or classmates without IRB review. Use public data and your own artifacts (STUDY_PROTOCOL.md template).
  • Sources: The Register · LWN

Where sources disagree ​

  • AI reviewers and cycle time. At Beko, PR-Agent's comments were 73.8% resolved but closure time rose 42%; at Atlassian, PR cycle time fell 30.8% (Cihan et al.; Tantithamthavorn et al.). Different settings, different outcomes: don't quote either as "the" effect.
  • Cursor's effect on complexity. He et al. report +40.7% in a table and 25.1% in the text (arXiv 2511.04427).
  • SWE-Bench Pro scores. The paper's tables, its conclusion and vendor claims on aggregators disagree (Deng et al.).
  • The kernel's Assisted-by tag. Earlier notes described it as current; as of November 2026 it is gone from the master policy (E4).
  • SWE-bench Verified flaw rate (D1) comes from coverage, not from OpenAI's page.
  • Sibling-course cases [A] were verified by that course in September–October 2026 and not re-opened here. The two MCP advisories in the tool notes (GHSA-m84r-3mrm-j4p8, GHSA-6qxp-vccf-f47h) were not opened at all: verify before putting them on a slide.
