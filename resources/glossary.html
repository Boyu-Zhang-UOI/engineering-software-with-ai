Glossary ​

AI-specific and course terms, with short definitions and the week that teaches each one. Basic software engineering terms (CI, refactoring, test double, race condition) are assumed, not defined. Product limits, prices and model names are in Tool Handout, never here.

Jump to: A · B · C · D · E · F · G · H · I · J · L · M · O · P · Q · R · S · T · V · W

A ​

Agent ​

An LLM in a loop with tools: it receives a task, decides on a tool call, the harness runs it and returns the result, and the loop continues until the model stops or a limit is hit. A coding agent's tools read and write files and run commands. You run, read and extend one in week 1 (mini-agent). Week 1.

Agent loop ​

The cycle at the core of every agent: send the conversation and tool schemas to the model → receive either text or a tool call → run the tool (after approval) → append the result → repeat. Termination conditions (no tool call, a step limit, a budget) are part of the design. Week 1.

AGENTS.md ​

A Markdown file at the root of a repository giving coding agents standing instructions: commands, architecture, conventions, scope, what never to do. Many harnesses read it automatically. It is advice, not enforcement: an agent can ignore it, so permissions and sandboxes do the enforcing. In 441 repositories, agent-first projects without a committed configuration file saw complexity rise 53% against 27% with one (Denisov-Blanch et al.). Template: AGENTS.md template; patterns: Agent Patterns: AGENTS.md structure. Week 3.

Agentic engineering ​

Building software with agents while keeping humans responsible for the specification, the verification and the result. Contrast with vibe coding. Week 1.

Agentic workflow ​

An automated job (for example GitHub Agentic Workflows, which compile Markdown into Actions YAML) in which an agent runs without a human at the keyboard. Each run spends from an allowance, so the per-run cap must be set below any free allowance (safety contract rule 6). Week 13.

AI_LOG.md ​

The course's disclosure file, in every repository: each significant AI session with its tool and model, what was delegated, what was verified and how. Template: AI_LOG.md template. Week 1.

AI reviewer ​

A bot that comments on pull requests (CodeRabbit, PR-Agent, Copilot code review). Measure it like any classifier: precision against a defect key, and how often its comments lead to changes (38.7% of AI comments vs 44.45% of human comments at Atlassian: Tantithamthavorn et al.). Week 9.

Approval gate ​

The point in a harness where a human must confirm a tool call before it runs. mini-agent requires a y for every command and write unless the exact command is on an allowlist. An approval policy decides what needs approval. Week 1.

Approval test ​

A characterization test that runs many inputs through the code, records every output and side effect in one file, and fails when a later run differs from that approved file; also called a golden master. Scrub what changes on every run (random IDs, the clock), and read the file before you approve it: approving is a claim. Week 8.

Assisted-by trailer ​

The last line of an AI-assisted commit message: Assisted-by: [tool and model]. The convention is LLVM's. Detection of agent-written commits is unreliable, so recorded attribution is the evidence (Horikawa et al.). Week 1.

Autopilot mode ​

Any agent setting that runs commands or writes without asking (also called auto-approve, "yolo" or skip-permissions mode). Banned in this course (rule 2). Week 1.

B ​

Background agent ​

An agent that runs remotely on a task (often from a GitHub issue) and returns a branch or pull request, while you do something else. Also cloud agent. Week 13.

Beat ​

A planned change to a specification partway through an assignment ("v1 against a spec, then the spec changes under you"), from UT Austin CS 378's homework design. Week 5's assignment has one. Week 5.

Benchmark contamination ​

When a benchmark's tasks or solutions were in a model's training data, so a score measures memory rather than skill. Date-windowed benchmarks compare tasks before and after a model's cutoff. See case D4. Week 12.

C ​

Canary ​

A fake, worthless secret (CANARY-…) planted to detect a leak: if it shows up somewhere it shouldn't, something exfiltrated it. The week 4 injection lab uses one. Week 4.

Characterization test ​

A test that records what existing code does now, right or wrong, so a refactor can prove it changed nothing. Week 8.

Check first ​

Writing the test or acceptance check before asking an agent for the code, in a separate prompt or session, so the check isn't bent to fit the code. Tests generated after faulty code caught 14% of its faults against 25% for tests generated independently (Konstantinou et al.). Week 5.

Checkoff ​

The last 15 minutes of each Lab, when staff check the week's in-lab deliverable. Every week.

Class codebase ​

The real open-source project the instructor forks for the class each term; teams work in their own forks of that class fork. Current pick: Tool Handout: The class codebase; details: The Class Codebase. Week 2.

Cohen's kappa (κ) ​

Agreement between two raters corrected for chance: 1 is perfect, 0 is chance level. Report it alongside percent agreement for an LLM judge, because a judge that always says "pass" agrees 95% of the time with labels that are 95% passes, yet κ is 0 (Thakur et al.; Husain). Week 12.

Compaction ​

Replacing older parts of an agent's conversation with a summary when the context fills up, so the session can continue. It loses detail, which is one reason to keep tasks small. Week 2.

Context engineering ​

Deciding what goes into a model's context, and what stays out: instructions, specifications, tools, retrieved files, history. More is not better (see context rot). Week 3.

Context rot ​

Performance falling as input length grows. In all 18 models Chroma tested, performance degraded with longer inputs, faster with distractors; a focused prompt of about 300 tokens beat the full 113K-token one (Hong et al.). Week 3.

Context window ​

The maximum number of tokens a model can read in one request: system prompt, tool schemas, conversation and files together. A local model's configured context can be much smaller than the model's maximum (local models). Week 1.

Criteria drift ​

The finding that grading a model's outputs changes your grading criteria, and that some criteria appear only after you see outputs (Shankar et al.). So don't freeze an eval rubric before looking at data. Week 12.

D ​

Dependency confusion ​

An attack on how package names resolve: someone publishes a package on the public registry under a name your project uses only internally, usually with a higher version, and a misconfigured install picks the public one. Controls: scoped names mapped to your registry, a lockfile with resolved URLs and integrity hashes, and npm ci in CI. A relative of slopsquatting. Week 10.

Dev container ​

A Docker container defined by .devcontainer/devcontainer.json, used by both Codespaces and VS Code locally. Its config runs commands when it's built, so read one before you use it (sandboxes). Week 0.

Due-date quiz ​

A 7-minute, 🔴 AI-off quiz at the start of the Seminar on the day an assignment is due, about that assignment (UT Austin CS 378's practice). Weeks 2–14. Due-Date Quizzes. Weeks 2–14.

E ​

EARS ​

Easy Approach to Requirements Syntax: acceptance criteria in fixed patterns. The course's default is the event-driven form WHEN trigger THE SYSTEM SHALL response; others are WHILE (state), IF … THEN (unwanted behavior), WHERE (optional feature) and the plain ubiquitous SHALL. Template: SPEC.md template. Week 5.

Egress block ​

A rule that lets a process reach only allowlisted hosts, removing an agent's way to send data out. Enforced by the network (a firewall, a sandbox), it is a control; enforced by a harness inspecting command strings, as in week 4's injection-lab, it is a speed bump that encodings and other tools can get past. Week 4.

Equivalent mutant ​

A mutant that behaves identically to the original program, so no test can kill it. It lowers the mutation score without indicating a weak test; deciding equivalence takes judgment (or a detector: Meta's reached 0.95 precision, Foster et al.). Week 7.

Eval ​

A repeatable measurement of an LLM feature or agent on a fixed set of cases, with a metric and, ideally, error bars. Capability evals ask what it can do; regression evals check that it still does what it did (Anthropic). Weeks 11–12.

Excessive agency ​

OWASP's name for giving an LLM system more tools, permissions or autonomy than its task needs. Third in the 2026 LLM Top 10, up from sixth (OWASP). Week 4.

Exploit test ​

A test written from the attacker's side: the attacker's request, exactly as they would send it, then an assertion of the response the specification requires (403, 400) and that nothing changed. Scanners find dangerous patterns in code; an exploit test checks behavior (who may do what, with which input), and once it passes it pins the control, so no later refactor removes it unnoticed. Week 10.

F ​

Final presentation ​

The finals-week event: each team presents its contribution with a live demo, in the scheduled final exam period. There is no final examination. The Final Presentation. Week 16.

Fine-grained token ​

A GitHub personal access token limited to selected repositories, specific permissions and an expiry date. The course's only kind of token for agents and CI (api-keys). Week 4.

Free tier ​

A no-cost allowance on a metered service. In this course, every free tier has no payment method behind it, so its spending cap is zero. Current allowances: Tool Handout: Spreading the work across free allowances. Week 0.

G ​

Goldfish test ​

Give a fresh agent session (one with no memory of your work) only a document, such as SPEC.md, TASKS.md or AGENTS.md, and see whether it can work from that alone. Wherever it guesses or asks, the document is leaning on context that lives in your head. From Michigan EECS 498's Elephant-Goldfish Model. Agent Patterns: The Goldfish test. Weeks 3 and 5.

Grace token ​

One of two 48-hour extensions each student may use on labs and assignments; not on quizzes, oral exams, the PR round or the final presentation. Assessment. Week 1.

H ​

Harness ​

Everything around the model in an agent: the system prompt, tool definitions and their implementations, the loop, context management, permissions and sandboxing. A score belongs to model plus harness: scaffolds alone shift benchmark scores by tens of points (evidence notes). Week 2.

Human in the loop ​

A design in which a person approves or reviews agent actions at defined points. Most open-source AI policies require it (Hora & Robbes). Weeks 1 and 13.

I ​

Indirect prompt injection ​

Prompt injection delivered through content the agent reads rather than through the user: a README, an issue, a web page, a tool result, a code comment. Week 4.

J ​

JSON-RPC ​

A small protocol for remote procedure calls in JSON ({"jsonrpc": "2.0", "id": 1, "method": "tools/list"}). MCP is built on JSON-RPC 2.0; over stdio, each message is one line. Week 3.

L ​

Lethal trifecta ​

Simon Willison's name for an agent with access to private data, exposure to untrusted content and a way to send data out. With all three, prompt injection can make it leak the data. Remove a leg per session (case A1). Week 4.

LLM-as-judge ​

Using a model to grade another model's outputs. A judge is a model of a human grader, so calibrate it against human labels and report κ, true-positive and true-negative rates, not just agreement. Week 12.

Local model ​

A model run on your own hardware or the lab machine, typically through Ollama. Private and unlimited, but weaker, and sensitive to its configured context window (local models). Weeks 0–1.

M ​

MCP ​

Model Context Protocol: an open protocol, built on JSON-RPC, through which an agent (the client) discovers and calls tools offered by a server, over stdio or HTTP. Writing a server means implementing methods such as tools/list and tools/call. The spec's current version and SDKs are in Tool Handout: Free infrastructure. Week 3.

Mutation score ​

The share of mutants a test suite kills (excluding equivalent ones). A better measure of test adequacy than coverage: suites with 100% coverage can have very low mutation scores (MutGen), though both measures are unreliable when the code may already be buggy (Zhao, Zhou & Cohen). Week 7.

Mutation testing ​

Making small deliberate changes (mutants) to code, such as < to <=, and running the tests: a test that fails kills the mutant; a surviving mutant shows a behavior no test checks. Tools: StrykerJS (JavaScript), mutmut (Python). Week 7.

O ​

Observed and inferred ​

The course's claim tags, from Stanford CS146S. Observed: you ran it or read it, and can show the output or the line. Inferred: you or an AI concluded it. Only observed claims count as verified. Week 1.

Ollama ​

An open-source server that runs local models and exposes an OpenAI-compatible API on port 11434. Configure its context length for agents (local models). Week 0.

OpenAI-compatible API ​

An HTTP API that accepts OpenAI's chat-completions request format (/chat/completions, messages, tools). Most providers and Ollama offer one, which is why the kits switch provider with three environment variables (api-keys). Week 1.

Oral exam ​

A 15-minute, individual, 🔴 AI-off exam in weeks 8 and 14, about your own work. Oral Exams. Weeks 8 and 14.

Oracle ​

What decides whether a test's output is correct. LLM-generated oracles tend to capture what the code does rather than what it should do, which hides bugs (Konstantinou, Degiovanni & Papadakis). Week 6.

P ​

pass@k and pass^k ​

pass@k: the probability that at least one of k attempts succeeds (a capability measure). pass^k: the probability that all k attempts succeed (a reliability measure). In τ-bench, pass^8 was below 25% in retail (Yao et al.). Week 12.

Plan mode ​

A harness mode in which the agent may read and propose a plan but not edit or run anything until you approve. Agent Patterns: Plan first. Week 5.

PR round ​

Weeks 9–10: each student opens one pull request on another team's fork, and the receiving team reviews it and decides. From UT Austin CS 378. The PR Round. Weeks 9–10.

Precision and recall ​

For a reviewer (human or AI) scored against a defect key: precision is the share of its comments that point at real defects; recall is the share of real defects it found. Week 9.

Prompt injection ​

Text that makes a model follow instructions its user didn't give. Direct comes from the user's input; indirect arrives in content the model reads. First in OWASP's 2026 LLM Top 10. Week 4.

Property-based testing ​

Testing a function against a stated property ("no two bookings overlap") on many generated inputs, with automatic shrinking of failures to a minimal case. Tools: fast-check (JavaScript), Hypothesis (Python). Week 6.

Q ​

Quarantined reading ​

A defense in which untrusted text is processed by a model call that has no tools, and only a constrained result (a summary, a field) reaches the agent that can act. Also the dual LLM pattern (Beurer-Kellner et al.; CaMeL). Week 4.

R ​

Ratchet ​

A CI gate on old code that blocks only what a pull request makes worse: lint only the files it changes, or report only the findings introduced since its base commit. Existing warnings don't block anyone, and no PR adds new ones; a gate that is red on main forever teaches everyone to ignore red. Week 9.

Rate limit ​

A provider's cap on requests or tokens per minute or day. Exceeding it returns HTTP 429; well-behaved clients retry with exponential backoff. Free-tier limits: Tool Handout: Spreading the work across free allowances. Week 1.

Recorded responses ​

Saved model outputs that let tests and CI run an eval offline and deterministically, with no key and no cost. The eval-harness kit's tests use them. Week 12.

Retrieval-augmented generation (RAG) ​

Fetching relevant documents and putting them in the prompt. It has known failure points (missing content, missed top-ranked documents, wrong specificity…) and "can only be fully validated in operation" (Barnett et al.). Week 11.

S ​

Safe Loop ​

The inner loop inherited from the sibling course: Describe → Plan → Step → Test → Read → Commit. Specify · Delegate · Verify, and the Safe Loop. Week 1.

Sandbox ​

An environment that limits what an agent can reach: a Codespace, a dev container, a microVM. It moves the blast radius rather than removing it; filesystem and network isolation are both needed (sandboxes). Weeks 0, 2 and 4.

SBOM ​

Software bill of materials: a machine-readable list of every component you ship, by name and version (week 10 generates one with npm sbom). When the next advisory lands, it answers "are we affected?" in a minute; it doesn't show that any component is safe. Week 10.

Seam ​

A place where you can change a program's behavior without editing the code there (an injected dependency, a module boundary), used to get legacy code under test. Week 8.

Seeded bug ​

A bug planted on purpose in a kit for students to find; roomly has several, listed only in the instructor's answer key. Weeks 6–7.

Skill ​

A folder of instructions (a SKILL.md, sometimes scripts) that an agent loads when a task matches its description. A skill can make the agent do anything it is allowed to do: read one before you adopt it (rule 8). Week 3.

Slopsquatting ​

Registering package names that models tend to invent, so an agent that installs an invented dependency installs malware (case B5). Week 10.

Specify · Delegate · Verify ​

The course's core triad, from UT Austin CS 378: before you start, decide what you will specify, what you will delegate to an agent, and how you will verify it. Specify · Delegate · Verify, and the Safe Loop: Specify · Delegate · Verify. Week 1.

Strangler fig ​

A way to migrate code by growing the new implementation around the old: route one call at a time to the new code, run both and compare their results (a parallel run) while the old path stays authoritative, and delete the old path last. Martin Fowler's name, after a vine that grows around a tree. Week 8.

Structured output ​

Constraining a model to return output matching a schema (JSON Schema, a grammar), by API feature or constrained decoding. Validate it anyway, and retry on failure. Week 11.

Subagent ​

A separate agent session started by a parent agent for a sub-task, with its own fresh context, returning only a summary. Useful for keeping the parent's context small. Agent Patterns: Subagents. Week 2.

SWE-bench ​

A family of benchmarks in which an agent must resolve real GitHub issues so that held-out tests pass. Every major variant has been shown to overstate capability (benchmark inflation). Weeks 1 and 12.

System prompt ​

The instructions a harness sends before the conversation: role, rules, and usually the tool schemas. In week 1's trace dissection you read a real one. Week 1.

T ​

Time horizon ​

METR's measure of agent capability: the length of task (in human expert time) an agent completes with 50% reliability. It has been doubling roughly every 7 months since 2019 (Kwa et al.). Weeks 1 and 15.

Token ​

The unit a model reads and writes, roughly three-quarters of an English word. Context windows, rate limits and prices are counted in tokens. Week 1.

Tool call ​

A model's structured request to run a named tool with JSON arguments (for example list_files with {"path": "src"}), which the harness executes and returns. The model never runs anything itself. Week 1.

Tool poisoning ​

Hiding instructions in an MCP tool's description or metadata, which the model sees and the user usually doesn't (case A3). Week 4.

Trace ​

A record of every request and response in an agent session. mini-agent writes one as JSONL; week 1's trace dissection reads one from a real agent. Week 1.

V ​

Vibe coding ​

Accepting AI-written code without reading it, in Andrej Karpathy's original sense; fine for a throwaway, not for software anyone relies on. Where this course starts its story, not its practice. Week 1.

W ​

Worktree ​

A second (or third) working directory attached to the same git repository, each on its own branch: git worktree add ../roomly-issue-3 -b issue-3. It lets several agents work in parallel without touching each other's files. Agent Patterns: Worktrees. Week 13.
