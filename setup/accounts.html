Accounts ​

Which accounts the course uses, when you need each one, and the settings to change on day one.

Every account here is free and none needs a payment method. You are an adult with a GitHub account already, so this page is short: it says when each account is needed and what to switch off. Which product fills each slot, and its current limits, is in Tool Handout: The stack at a glance.

TIP

When a service offers Sign in with GitHub and then asks for repository access, choose Only select repositories and pick the one repository it needs. An app with access to every repository you own is a large blast radius for a review bot.

GitHub and the Student Developer Pack ​

Apply at education.github.com with your UIdaho email or a photo of your student ID. Verification takes days, and GitHub re-checks eligibility monthly. GitHub has paused new Copilot Student sign-ups before (Tool Handout: The GitHub Student Developer Pack), so apply early and use Copilot Free while you wait.

What matters for the course:

  • Copilot Student's model allowance is tiny. Use it for completions and Ask mode, and for occasional short agent runs. The course's heavy agent work runs on other free pools and the lab machine (spreading the work). Don't set a paid budget to keep going: switch tools instead.
  • Codespaces hours are core-weighted. A 4-core machine uses your hours twice as fast as a 2-core one. Use the smallest machine that builds the class codebase, and stop it when you finish.
  • Actions is free on public repositories. Team forks are public, so CI costs nothing there. Private repositories draw on a monthly entitlement.

One free LLM API key ​

The kits read LLM_BASE_URL, LLM_API_KEY and LLM_MODEL and work with any OpenAI-compatible provider, so the key you choose is a configuration detail, not a commitment. Get the primary key from Tool Handout: LLM APIs for the kits in week 0 and a fallback key in week 1. Both accounts must have no payment method: on a free tier, that is the hard spending cap (contract rule 6). How to store and use them: API Keys, Tokens and Spending Caps.

Use a personal Google account for AI Studio. Institutional accounts may have it switched off, and their terms differ.

The chat assistant ​

The chat assistant is for thinking, not for the labs' agent work: explaining a paper's method, checking your reasoning about a design, drafting questions for a maintainer (which you then rewrite in your own words). Graded writing (reading responses, reflections, PR descriptions, review comments you sign, critiques) is 🔴 AI off (syllabus).

Use one primary assistant and know your fallback. When you quote what an assistant told you in a report, tag it inferred until you've checked it yourself.

Canvas ​

Canvas holds everything graded that is personal. The rule is simple: if it's about you or names a classmate, it goes on Canvas; if it's code, specs, tests, AI_LOG.md or a PR, it goes in the repository.

Security hygiene ​

You know the basics. The course-specific points:

  • Two-factor authentication on GitHub and Google, with recovery codes in a password manager.
  • A password manager holds your keys, not a notes app or a dotfile in a repository.
  • Review authorized apps at github.com → Settings → Applications at the start of each team phase, and revoke what you no longer use.
  • Revoke course keys and tokens at the end of the term. Any key that was ever pasted into a chat or committed is revoked the same day (API Keys, Tokens and Spending Caps: If a key leaks).
  • Keep course work separate from employer work. Don't open an employer's repository in a course Codespace, and don't connect course agents to work accounts.

Checklist ​

  • ☐ Canvas sign-in works
  • ☐ Personal GitHub account with 2FA, private email, recovery codes saved
  • ☐ GitHub Education applied for
  • ☐ Copilot and chat-assistant training settings off
  • ☐ Primary LLM API key (week 0) and fallback key (week 1), no payment method on either
  • ☐ Jules (by week 12) and CodeRabbit (week 9) when those weeks arrive
