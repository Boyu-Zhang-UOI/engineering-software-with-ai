Local Models: Ollama on a Laptop and on the Lab Machine ​

Unlimited, private inference for the kit labs and evals, if you configure the context window. Model names, sizes and versions are in Tool Handout: The lab machine and local models.

Why the course uses local models. Free API tiers are small and may train on your prompts. A local model costs nothing per request and keeps prompts on the machine. It is also weaker than a frontier model, and that is useful: Michigan's EECS 498 runs on small local models on purpose, because "a small model punishes sloppy engineering visibly" (Michigan syllabus). Use local models for mini-agent, mcp-from-scratch, eval-harness (as subject or judge) and small fixes. Don't expect them to navigate the class codebase the way a frontier model does.

WhereWhat it runsWho it's for
The lab machine (a 24–32 GB GPU)Mid-size coding models at a 64K context, served to the class as one queueEveryone, through its API
Your laptop (16 GB of RAM or more)Small models, for the kit labsOptional; a private, always-available fallback
Neither—The free API tiers cover every lab (API Keys, Tokens and Spending Caps: Switching provider, or using the lab machine)

The 64K-context setting, and why tool calls fail silently without it ​

A model's context window is how many tokens it can read in one request: system prompt, tool schemas, conversation and file contents together. Ollama sets a default context from your GPU memory, and on most laptops and smaller GPUs the default is a few thousand tokens (TOOLS.md has the thresholds). An agent's first request is larger than that: the system prompt plus the JSON schema of every tool is often several thousand tokens before you've asked anything.

When a request is longer than the context, Ollama truncates it and carries on. There is no error. The model simply never sees part of the prompt, typically the instructions and tool definitions. What you see:

  • the model answers in prose, or prints a bash command as text, instead of returning a tool_calls entry;
  • the agent loop "finishes" after one turn because the reply has no tool call;
  • behavior changes when the conversation gets longer, though nothing in your code changed.

Ollama's documentation says agents and coding tools should be given at least 64,000 tokens (Ollama: context length). The setting is per server, through an environment variable, because the OpenAI-compatible endpoint the kits use has no per-request context option:

bash
OLLAMA_CONTEXT_LENGTH=64000 ollama serve

A larger context needs more memory. If the model plus a 64K context doesn't fit in GPU memory, Ollama moves part of it to the CPU and everything slows down sharply; that's the signal to use a smaller model, not a smaller context.

On a laptop ​

  1. Check your memory. 16 GB of RAM is the practical minimum for the small models TOOLS.md lists. Close other heavy programs while a model runs.

  2. Install Ollama from ollama.com/download. It installs a local server on port 11434.

  3. Start the server with the 64K context.

    • Linux, or any system from a terminal: quit any running Ollama, then run OLLAMA_CONTEXT_LENGTH=64000 ollama serve and leave that terminal open.
    • macOS app: launchctl setenv OLLAMA_CONTEXT_LENGTH 64000, then quit and reopen the Ollama app.
    • Windows app: add a user environment variable OLLAMA_CONTEXT_LENGTH = 64000 (Settings → System → About → Advanced system settings → Environment Variables), then quit and restart Ollama.

  4. Pull the laptop model named in TOOLS.md:

    bash
    ollama pull [laptop model from TOOLS.md]

  5. Point a kit at it, in the kit's .env:

    text
    LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=[laptop model from TOOLS.md]

  6. Run the smoke test below.

A Codespace can't reach localhost on your laptop. To use a laptop model, run the kit on your laptop, ideally in a dev container (Sandboxes: Codespaces and Dev Containers: Dev containers on your laptop).

The tool-calling smoke test ​

Run it once with no padding, then with padding that pushes the request past a small default context. Both should return a tool call. If the padded one doesn't, the context setting isn't in effect.

bash
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_MODEL="[model from TOOLS.md]"
export PAD=0      # then try PAD=2000

python3 - <<'EOF' | curl -s "${LLM_BASE_URL%/}/chat/completions" -H "Content-Type: application/json" -H "Authorization: Bearer ${LLM_API_KEY:-ollama}" --data @- | python3 -c "import json,sys; m=json.load(sys.stdin)['choices'][0]['message']; print('TOOL CALL:', m['tool_calls'][0]['function']) if m.get('tool_calls') else print('NO TOOL CALL:', (m.get('content') or '')[:200])"
import json, os
pad = "This sentence is padding for the context-length check. " * int(os.environ.get("PAD", "0"))
print(json.dumps({
    "model": os.environ["LLM_MODEL"],
    "messages": [
        {"role": "system", "content": "You are a coding agent. Always use a tool to inspect files. " + pad},
        {"role": "user", "content": "Which files are in the folder src? Use your tool."},
    ],
    "tools": [{"type": "function", "function": {
        "name": "list_files",
        "description": "List the files in a folder of the workspace",
        "parameters": {"type": "object", "properties": {"path": {"type": "string"}}, "required": ["path"]},
    }}],
}))
EOF

✅ Checkpoint: both runs print TOOL CALL: with list_files and a path like src. Record the model, the padding and the result in your AI_LOG.md: that's an observed claim about your setup. The same script works against the lab machine or a free API: change LLM_BASE_URL, LLM_MODEL and LLM_API_KEY.

If the unpadded run already prints NO TOOL CALL, the model itself isn't reliable at tool calling, whatever the context. Some small models print the command they would run instead of calling the tool. Try the next model in TOOLS.md.

On the lab machine ​

The instructor runs Ollama on a lab machine with a 24–32 GB GPU, at a 64K context, with the models TOOLS.md lists. You use its API; you never log in to it.

  • Connecting. Your instructor gives you the host name and says how to reach it: from the campus network or VPN, or through an authenticated endpoint. A Codespace runs in the cloud, outside the campus network, so it can reach the lab machine only through that endpoint. Set LLM_BASE_URL=http://[lab-machine-host]:11434/v1 (or the address you're given) and LLM_MODEL to the lab model.
  • It's one queue for the whole class. One GPU serves one or a few requests at a time. A request may wait behind a team's batch. Expect seconds to minutes per agent turn at busy times.
  • Be a good neighbor. Batch work by team rather than running 30 agent loops at once; keep contexts lean; set a step limit and a timeout; don't leave a loop running unattended; retry with backoff on errors.
  • The data rule still applies. Prompts stay on the machine, which makes it the safest place to send a stack trace from your own code. It is still shared course infrastructure: no personal data, no secrets (contract rule 1).
  • When it's down or saturated, switch to a free API by configuration (API Keys, Tokens and Spending Caps: Switching provider, or using the lab machine). That's the planned fallback, not an emergency.

Free agent harnesses on a local model ​

Several CLI agents run against a local Ollama at no cost; TOOLS.md lists which, with the commands. Two cautions:

  • Each harness sends a much larger system prompt than mini-agent does. A harness that works on a 64K context may fail on a smaller one in exactly the silent way described above. OpenCode's own documentation requires 64K or more.
  • Some harnesses route requests to a hosted service by default. Check where requests go before you assume a session is local, and keep keys in your own environment variables rather than a hosted console.

Troubleshooting ​

  • The model replies in prose or prints a command instead of calling the tool → the local model ignores its tools
  • Everything is very slow → the model plus context doesn't fit in GPU memory; use the smaller model TOOLS.md suggests
  • connection refused on port 11434 → the server isn't running, or (for the lab machine) you're off the campus network: the lab machine is slow or unreachable
