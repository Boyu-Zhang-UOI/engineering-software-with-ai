Week 0 — Before the First Seminar ​

About 90 minutes of setup, so that week 1 starts with running and extending an agent, not signing up for things.

ItemDetails
Before the first SeminarAbout 90 minutes: accounts and the Student Developer Pack application, the data settings, one free LLM API key, a test Codespace, and a first read of the agent safety contract
During week 1Sign the agent safety contract on Canvas; follow up on GitHub Education if it hasn't been approved
You needA laptop with a modern browser, your phone (for two-factor authentication), and your UIdaho sign-in for Canvas
AI use🟢 AI on: asking a tool where a setting is · 🔴 AI off: the safety contract signature
Cost$0. No step needs a payment method, and the safety contract asks you not to add one (rule 6)

This course assumes you know git, the command line, and Python or JavaScript. It doesn't assume you have used a coding agent seriously, run a local model or written an MCP server; those are the course. Terms that are new are in the glossary. Product limits and model names are in Tool Handout, the only page that holds them.

Work through the steps in order. If one fails, keep going and bring the problem to the first Lab, or to office hours before it (if you get stuck).

#Do thisAbout

Step 1 — GitHub and the Student Developer Pack (15 min) ​

Details: Accounts.

  1. Use a personal GitHub account you'll keep after graduating. If your only account is managed by an employer, make a separate one.
  2. Turn on two-factor authentication (a passkey or an authenticator app) and save the recovery codes in a password manager.
  3. Settings → Emails → tick Keep my email addresses private and Block command line pushes that expose my email. Your commits will be in public forks.
  4. Apply for GitHub Education with your UIdaho email or student ID. It gives you Copilot Student and GitHub Pro's larger Codespaces and Actions allowances. Verification can take days, so do this first. While you wait, turn on Copilot Free.

✅ Checkpoint: GitHub asks for your second factor on a new browser, and the Education application shows as submitted.

Step 2 — Data settings (10 min) ​

The course's data rule (contract rule 1): free tiers may train on your prompts, so use them only on public open-source code and the course kits. Before you type anything:

  • Copilot: github.com/settings/copilot/features → turn off use of your data for training. While you're there, set Suggestions matching public code to Block.
  • Your chat assistant (Claude Free or ChatGPT Free, or Microsoft Copilot with your UIdaho sign-in): turn off the "improve the model" setting.
  • Google AI Studio (step 3) has no opt-out on the free tier, and human reviewers may read prompts. That's why the data rule exists.

Menus move. If a setting isn't where this page says, ask the tool where it is. More: Accounts: Privacy settings.

✅ Checkpoint: for each tool, you can point to the setting you changed, or you know it has no opt-out.

Step 3 — One free LLM API key (20 min) ​

Every course kit talks to a model through an OpenAI-compatible API configured by three environment variables: LLM_BASE_URL, LLM_API_KEY and LLM_MODEL. Get one key now; the primary provider and its base URL are in Tool Handout: LLM APIs for the kits.

  1. Sign in to Google AI Studio with a personal Google account (school accounts often have it switched off) and create an API key. Don't add billing.
  2. Store the key in your password manager, not in a document or a chat.
  3. Create a second key with the fallback provider in TOOLS.md, also with no payment method. You'll need it the first time the primary is rate-limited, which in this course is a matter of when.

You'll test the key in step 4, inside a Codespace, so it never touches your laptop's shell history. How to handle keys from here on: API Keys, Tokens and Spending Caps.

Step 4 — A test Codespace (20 min) ​

Every lab runs in a GitHub Codespace, and untrusted code always does (contract rule 3). What a Codespace protects you from, and what it doesn't: Sandboxes: Codespaces and Dev Containers.

  1. Create a private repository called eswa-practice with a README.

  2. Code → Codespaces → Create codespace on main.

  3. In the terminal, check the versions. The kits need Node 20.12 or later, and the testing weeks need Node 22 (TOOLS.md has the exact versions):

    bash
    node --version
git --version
python3 --version

  4. Add your key as a Codespaces secret for this repository only: github.com → Settings → Codespaces → New secret, name LLM_API_KEY, repository eswa-practice. Reload the codespace when VS Code offers. Then set the two non-secret variables for this terminal session, with the values from TOOLS.md:

    bash
    export LLM_BASE_URL="[base URL from TOOLS.md]"
export LLM_MODEL="[model ID from TOOLS.md]"
test -n "$LLM_API_KEY" && echo "LLM_API_KEY is set"

  5. Send one request. The command strips any trailing slash from the base URL and never prints the key:

    bash
    curl -s "${LLM_BASE_URL%/}/chat/completions" \
  -H "Authorization: Bearer $LLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"model\": \"$LLM_MODEL\", \"messages\": [{\"role\": \"user\", \"content\": \"Reply with the word ready.\"}]}"

  6. Open the Copilot chat in Ask mode and ask it what ${LLM_BASE_URL%/} does in bash. Check its answer against the bash manual's "parameter expansion" section: that's the course's verification habit in miniature.

  7. Stop the codespace (github.com/codespaces → … → Stop). Running codespaces use up your monthly hours.

✅ Checkpoint: the response contains JSON with "choices" and the word ready; Copilot answered in the chat; the codespace is stopped. A 401 means the key is wrong; a 404 usually means the base URL or model ID is (troubleshooting).

Step 5 — The lab machine, and optionally your laptop (15 min) ​

The class has a lab machine that serves open-weight models through Ollama, one shared queue for everyone (Local Models: Ollama on a Laptop and on the Lab Machine: On the lab machine).

  1. The lab machine. Your instructor's week 0 message gives its address and how to reach it (the campus network or VPN, or an authenticated endpoint that also works from a Codespace). Run the tool-calling smoke test against it with the lab model from TOOLS.md. If you haven't received the address yet, do this in the first Lab instead.
  2. (Optional) your laptop. If it has 16 GB of RAM or more, install Ollama, start it with the 64K context and run the same smoke test. It gives you an unlimited, private fallback for the kit labs. If your laptop is smaller, skip this: the lab machine and the free APIs cover you.

✅ Checkpoint: the smoke test printed TOOL CALL: against the lab machine (or you know when you'll try it).

Step 6 — Read the agent safety contract (10 min) ​

Read the agent safety contract. Its eleven rules exist because of real incidents, and you'll sign it on Canvas in week 1. Write down any rule you think is wrong or unclear and bring it to the first Seminar: disagreeing with a rule, with a reason, is a good start to this course.

✅ Checkpoint: you can say why an agent that reads a stranger's GitHub issue must not have your real keys within reach.

You're ready for the first Seminar when ​

  • ☐ I can sign in to Canvas.
  • ☐ My GitHub account has two-factor authentication and private email on, and my GitHub Education application is in.
  • ☐ Copilot's training setting is off, and so is my chat assistant's.
  • ☐ I have a primary and a fallback LLM API key, both with no payment method, stored in a password manager.
  • ☐ My key worked from a Codespace without ever being printed, and the codespace is stopped.
  • ☐ The tool-calling smoke test passed against the lab machine (or I know when I'll run it).
  • ☐ I read the safety contract and wrote down my questions.
  • ☐ I know where Tool Handout and troubleshooting are.

During week 1 ​

  • Sign the agent safety contract on Canvas (10 min). It is personal: don't commit it to a repository.
  • GitHub Education. If it isn't approved by the end of week 1, tell your instructor. Copilot Free covers week 1; Copilot Student matters from week 2.
  • Read the week 1 page and its "Before the Seminar" row.

If you get stuck ​

  1. Check Troubleshooting.
  2. Ask the tool's own assistant where a setting is. Never paste a key, password or recovery code into it.
  3. Email your instructor before the first Seminar with what you tried and the exact error. Account problems are far easier to fix before week 1 than during it.
